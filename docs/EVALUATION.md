# Evaluation Framework & Benchmark Results

This document presents the evaluation methodology, offline benchmark results, synthetic simulation metrics, known limitations, and instructions for live pipeline evaluation for the **Unstuck** AI coding tutor extension.

---

## 1. Evaluation Methodology

The Unstuck tutoring architecture uses a multi-agent StateGraph pipeline:
1. **Context Builder:** Scrapes active problem statements, DOM context, user code, and submission history, strictly delimiting web text in untrusted data blocks (`Rule 3`, `EC-029`).
2. **Hint Generator:** Generates level-constrained pedagogical guidance using Gemini structured outputs.
3. **Critic Guardrail:** Deterministically intercepts code leaks (prohibiting syntax, code fences, and function declarations in L1 and L2) and verifies that `groundedQuote` exists verbatim within the original problem statement.
4. **Retry & Fallback:** Retries hint generation up to 2 times upon critic rejection; falls back to deterministic safe scaffold templates if retries are exhausted.

### Core Evaluated Metrics
- **L1/L2 Code Leak Rate (%):** Proportion of Level 1 (Direction) and Level 2 (Approach) hints containing executable code, function signatures, or code fences (Strict Definition of Done: **0.0%**).
- **Grounded Quote Rate (%):** Proportion of hints containing a verbatim quote anchored in the problem statement text.
- **Critic Agreement Rate (%):** Deterministic critic agreement with annotated ground-truth labels.
- **Latency (p50 / p95):** Latency of candidate verification and pipeline execution.
- **Nudge Acceptance Rate (%):** Ratio of accepted nudges to total nudges offered.

## 3. Synthetic Planner Simulation Results

> [!NOTE]
> **Honesty Disclosure:** The 200-session simulation evaluates the contextual bandit against a fixed threshold baseline using scripted probabilistic user personas. This is a **synthetic simulation, not an empirical user study**.

Across 200 scripted problem sessions simulating three distinct solver profiles (*Struggling Novice*, *Independent Solver*, and *Casual / Distracted*):

```text
===== STEP 7: 200-SESSION SIMULATION RESULTS (Synthetic simulation, not a user study) =====
Fixed Baseline:   185 nudges | 89 accepts | 71 dismissals | 48.1% acceptance rate
Contextual Bandit: 90 nudges | 73 accepts | 13 dismissals | 81.1% acceptance rate
====================================================================================
```

### Analysis
- **Intrusiveness Reduction:** The contextual bandit offered **51.4% fewer total nudges** (90 vs 185) by learning to suppress proactive nudges in high-dismissal context buckets (e.g. independent solvers working on hard problems).
- **Acceptance Rate Gain:** Nudge acceptance increased from **48.1%** to **81.1%** (+33.0% absolute improvement) by directing interventions toward struggling novices where acceptance likelihood is highest.

## 4. Limitations & Threats to Validity

1. **Small Benchmark Dataset:** The offline benchmark comprises 15 canonical coding problems (Two Sum, Valid Parentheses, Coin Change, Course Schedule, LRU Cache, etc.). It does not cover atypical interactive competitive programming platforms or esoteric dynamic programming variants.
2. **Author-Created Candidate Hints (Same-Team Judge Risk):** The synthetic candidate hints were authored by the development team. The regex heuristic rules and candidate hint texts may reflect shared syntactic assumptions that could overestimate leak prevention compared to unconstrained generative outputs.
3. **No Offline Quality Measurement:** The offline benchmark measures only regex leak detection and string grounding. It does not measure pedagogical appropriateness, mathematical correctness, or whether the hint truly guided a student to a solution.
4. **Single Model Target:** Prompt templates and schemas were designed and calibrated against Google Gemini (`gemini-2.5-flash`). Behavior on other model families has not been verified.
5. **Synthetic User Behavior:** The planner evaluation uses fixed persona probability distributions rather than longitudinal student telemetry.
6. **Chat vs Proactive Hint Grounding:** Proactive hints are guaranteed to anchor to problem statements via mandatory verbatim quotes. In conversational chat, students frequently submit off-topic or general inquiries (e.g., *"who invented this problem"*); the pipeline handles these via explicit unanswerable classifications (`answerable_from_page: false`), omitting fake quote extraction.

## 5. Live Evaluation Results (`npm run eval:live`)

> [!IMPORTANT]
> **Live Benchmark Status: Awaiting User Execution**
>
> In accordance with safety rules, automated runs do not hold live API keys. No live numbers are fabricated. Follow the instructions below to run the live pipeline on your machine with your Google Gemini API key.

### How to Run Live Evaluation
Run the live pipeline across all 15 benchmark problems at levels L1, L2, and L3:

#### Windows PowerShell:
```powershell
$env:GEMINI_API_KEY="your-gemini-api-key"
npm run eval:live
```

#### Bash / macOS / Linux:
```bash
export GEMINI_API_KEY="your-gemini-api-key"
npm run eval:live
```

#### Optional Environment Configuration:
```bash
# Override model ID (defaults to gemini-2.5-flash)
export GEMINI_MODEL="gemini-2.5-flash"
```

### Output Artifacts
When executed, `npm run eval:live` will sequentially query the Gemini API with rate-limiting backoff, run the Critic guardrails, and write the following files to `eval-output/`:
- `eval-output/live_evaluation_results.json`
- `eval-output/live_evaluation_results.csv`
- `eval-output/live_evaluation_results.md`
