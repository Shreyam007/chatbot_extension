# Live Smoke Test Guide (Unstuck v1.0.5 "STABILIZATION")

This guide provides step-by-step instructions for manually verifying **Unstuck v1.0.5** in real browsers (Chrome or Brave) on live coding platforms (such as `leetcode.com/problems/two-sum`), specifically confirming stabilization of S1–S4 symptoms, time-without-progress nudges, FAB activation, per-tab isolation, and free-tier Gemini rate limits.

---

## 1. Extension Installation

### Option A: Load Unpacked (Development / Production Build)
1. Build the extension:
   ```bash
   npm run build
   ```
2. Open Chrome or Brave and navigate to `chrome://extensions/` (or `brave://extensions/`).
3. Enable **Developer mode** toggle in the top-right corner.
4. Click **Load unpacked** and select the `.output/chrome-mv3` folder inside this repository.
5. Verify **Unstuck** appears with version **1.0.5** and no error badges on initial load.

### Option B: Packaged Release (.zip)
1. Verify the release archive `.output/unstuck-1.0.5-chrome.zip` was generated by `npm run zip`.
2. Extract the `.zip` archive into a local folder.
3. Load the extracted folder via **Load unpacked** in `chrome://extensions/`.

---

## 2. Initial Setup & Free-Tier Gemini Key Configuration

1. Click the Unstuck icon in the browser toolbar to open the Popup, or open Options: `chrome-extension://<id>/options.html`.
2. Configure Settings:
   - **API Key:** Enter your Google Gemini API Key (`AIza...`) and click **Test Connection**.
   - Verify green checkmark: *"Connected (X ms)"*.
   - **Low-Quota Mode:** Verify toggle is ON by default (conserves free-tier quota by capping agent graph to max 2 LLM calls per hint and skipping redundant LLM critic judges when deterministic safety checks pass).
   - **Nudge After (Minutes):** Default is 8 minutes (range 2–30 min).
3. Save settings.

## 3. Symptom Verifications (S1 – S4)

### Test Case S1: Clean Console & Handled Errors (No `[object Object]`)
1. Open `chrome://extensions/` (or Brave extension errors page).
2. Trigger an intentional error (e.g. disconnect Wi-Fi or enter an invalid key and request a hint).
3. **Verify:**
   - No `[Unstuck][AgentGraph][ERROR] hint_generator execution failed [object Object]` appears in the extension error log.
   - Any handled operational failures are routed to debug/warn logs with safe string serialization (`serializeLogData`).

### Test Case S2: Floating Action Button (FAB) Click on LeetCode
1. Navigate to: `https://leetcode.com/problems/two-sum/`.
2. Locate the floating star button (FAB) in the lower-right corner of the page.
3. When **no nudge is active**:
   - Click the FAB.
   - **Expected Behavior:** Unstuck Side Panel opens immediately via `chrome.sidePanel.open`.
   - If in a browser variant where `chrome.sidePanel.open` is restricted from content scripts, an in-page tooltip popover appears gracefully: *"Click the Unstuck toolbar icon to open the panel"*.
4. **Keyboard Activation:**
   - Tab to the FAB and press `Enter` or `Space`. It triggers panel open cleanly (with 100ms activation throttle preventing double execution).
5. **Context Menu:**
   - Right-click the FAB. A context menu opens offering: *Open Unstuck side panel*, *Pause Unstuck on this site*, *Snooze nudges for 30 min*.
6. **Green Dot Badge:**
   - The green badge is visible ONLY when an active nudge is offered, and disappears when no nudge is pending.

### Test Case S3: Stuck Detection with Time-Without-Progress
1. Stay on a LeetCode problem page without submitting code.
2. In regular mode, after `nudgeAfterMinutes` (default 8 min), or in **Demo Mode** after **20 seconds**:
   - The stuck detector ramps $P(\text{stuck})$ smoothly above the sensitivity threshold using the hyperbolic tangent ramp:
     $$P(\text{stuck}) = P_0 + (1 - P_0) \cdot \tanh\left(\frac{t - N_{\text{eff}}}{\tau}\right)$$
   - The FAB displays a gentle nudge with soft copy: *"You've been on this one a while. Want a hint?"*.
   - The green dot illuminates.
   - Clicking the FAB expands the card into the full nudge.
3. Open the Popup:
   - Check the **"Why no nudge yet?"** status box.
   - It displays clear diagnostic reasons (e.g. *"Bandit pacing"*, *"Contest mode active"*, or *"Looks like you're making progress (p=0.20, nudges at 0.60)"*).

### Test Case S4: Free-Tier Rate Limiting (429) & Daily Quota
1. When a 429 occurs:
   - The client parses Google AI headers and payload (`Retry-After`, `RetryInfo.retryDelay`, `QuotaFailure`).
2. **Per-Minute Rate Limit:**
   - Side panel displays `S13.3 Quota Rate Limited` with a live holding countdown.
   - Never displays *"0s remaining"* while limited; enables the *Retry Generation Now* button when countdown hits 0.
3. **Daily Quota Exhaustion:**
   - If Google AI signals daily quota (`per_day`), the side panel displays:
     - Title: **Daily Quota Exhausted**
     - Subtitle explaining limits reset at midnight Pacific Time.
     - Direct action buttons: *Switch Model in Options* and *Check Usage in AI Studio*.
     - **No network retry button** (prevents futile looping retries that waste quota).

## 4. Multi-Tab Context Isolation (Task D)

1. Open Tab A with LeetCode `two-sum`.
2. Open Tab B with LeetCode `add-two-numbers`.
3. Open Side Panel on Tab A: context shows *Two Sum*.
4. Open Side Panel on Tab B: context shows *Add Two Numbers*.
5. In background service worker, tab states are isolated in `tab-state.ts` and persisted in `chrome.storage.session`. Closing Tab A cleanly clears Tab A's state without polluting Tab B.
6. Neither tab fabricates fake statement texts (e.g. `Problem reference: ...`).
